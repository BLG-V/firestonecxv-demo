# 企业画像 × 产业链图谱 融合方案

> 定位：资深企业产业链管理视角的落地方案。回答"两个独立模块如何变成一个能替业务人员做判断的系统"，并给出配套的 Prompt 工程实施路径。
> 配套文件：`产业链融合_Prompt包.md`（可直接复制的提示词）、`enterprise_chain_profile.schema.json`（输出契约）。

---

## 0. 一句话结论

两个模块之间缺的不是"展示"，而是三层能力：**关联事实层**（企业到底挂在哪个环节上，且可核验）、**价值度量层**（环节价值 × 企业竞争力）、**可解释决策层**（招商档位 + 归因链 + 否决项）。补齐这三层，业务人员的四个问题才有系统答案，而不是靠人翻页面。

---

## 1. 现状诊断：四个断点

| 断点 | 业务表现 | 技术根因 |
|---|---|---|
| **定位断点** | 企业页看不到所属链/环节；图谱节点的企业清单靠人工维护、更新滞后 | 没有持久化的 `企业 ↔ 环节` 映射事实表；即便有，也多依赖单一行业分类码，粒度只能到"链"，到不了"环节/产品" |
| **价值断点** | 只有营收、专利、风险这类"企业自身"指标，说不出"它在这条链里值多少" | 价值度量缺少**环节侧维度**（稀缺度、附加值、战略重要性），企业评分与链结构完全解耦 |
| **决策断点** | "值不值得招商"靠经验判断，不同人结论不同，无法复盘 | 没有决策规则引擎；缺**落地可能性信号**（扩张迹象）与**本地载体匹配度**；缺硬性否决项 |
| **解释断点** | 系统给了标签或分数，但说不清凭什么，业务不敢用 | 打分过程未留存因子分解与原始证据，结论与数据字段之间没有可下钻链路 |

**关键判断**：这不是前端整合问题，是数据资产问题。把两个页面并排展示，四个问题一个都答不了。必须先建桥接域数据。

## 2. 目标形态：一次点击，回答四个问题

### 2.1 企业画像页 —— 新增"产业链定位"区块

一屏给出四段信息，每段都可下钻：

```
┌─ 产业链定位 ────────────────────────────────────────────┐
│ 【在哪】主链：新能源汽车产业链                            │
│         主环节：动力电池-电芯制造   置信度 0.91  规则+语义 │
│         次环节：电池回收-梯次利用   置信度 0.67            │
│         潜在环节：固态电池材料（募投项目指示）0.52          │
│                                                          │
│ 【值多少】产业链价值分 82.6 / 100   同链同环节排名 3 / 147 │
│         环节价值 88  ← 稀缺度 95｜附加值 84｜战略 90｜增长 82│
│         企业竞争力 ×1.16 ← 创新 强｜规模 中上｜资本 强      │
│         风险折减 ×0.87 ← 1 起行政处罚（已缴款结案）        │
│                                                          │
│ 【该不该动】招商档位 A（主动对接）  吸引力指数 78.4         │
│         扩张信号：近90天新增分支机构 2 家、招聘量 +180%     │
│         载体匹配：本地已有链主 X，其一级供应商缺口含电芯     │
│         否决项：无                                         │
│                                                          │
│ 【凭什么】展开 6 条归因 → 因子 → 字段 → 取值 → 来源 → 时间 │
│         数据缺口：未获取 2025 年营收；无海关进出口数据      │
└──────────────────────────────────────────────────────────┘
```

### 2.2 产业链图谱页 —— 节点点击后的三个新能力

1. **企业清单智能排序**：按 `匹配置信度 × 产业链价值分` 排序，标注"已确认/待核验/候选"三态。
2. **环节缺口分析**：本地该环节"应有企业画像 vs 实有企业"，输出缺什么档次、缺多少家、可从哪里补（跨区域候选企业 Top-N）。这是招商部门最想要的视图。
3. **链条健康度**：断链环节（本地为空）、弱链环节（仅有低竞争力企业）、强链环节（有链主）三色标注。

## 3. 六层架构

```
┌──────────────────────────────────────────────────────────┐
│ L5 应用层  画像页定位卡｜图谱节点下钻｜缺口看板｜线索推送    │
├──────────────────────────────────────────────────────────┤
│ L4 解释层  归因链四段式：结论→因子→字段→证据｜数据缺口声明   │
├──────────────────────────────────────────────────────────┤
│ L3 决策层  招商吸引力｜合作配套价值｜跟踪优先级｜硬性否决项   │
├──────────────────────────────────────────────────────────┤
│ L2 价值层  环节价值 SV × 企业竞争力 CF × 风险折减 RD        │
├──────────────────────────────────────────────────────────┤
│ L1 映射层  召回→精排→校准定档→人工核验（含弃权机制）        │
├──────────────────────────────────────────────────────────┤
│ L0 数据层  企业画像域｜产业链域｜★桥接域（新增）           │
└──────────────────────────────────────────────────────────┘
```

**架构原则**：L1 允许用 LLM（文本理解），L2/L3 **禁止** LLM 自由生成数值，一律走确定性计算；L4 负责把 L2/L3 的计算过程原样暴露。这条边界是整个系统可信度的地基。

## 4. L0 数据层：桥接域实体设计

### 4.1 核心表结构（PostgreSQL 语法，可平移到 MySQL/达梦）

```sql
-- ① 企业-产业链定位事实表（最核心，一切结论的锚点）
CREATE TABLE ent_chain_position (
    id                BIGSERIAL PRIMARY KEY,
    enterprise_id     VARCHAR(64)  NOT NULL,
    chain_id          VARCHAR(64)  NOT NULL,
    segment_id        VARCHAR(64)  NOT NULL,
    product_id        VARCHAR(64),                    -- 可空，粒度到产品时填
    region_code       VARCHAR(12),                    -- 区域维度，稀缺度计算依赖
    match_level       VARCHAR(16)  NOT NULL,          -- primary/secondary/potential
    match_score       NUMERIC(5,4) NOT NULL,          -- 校准后概率 0~1
    match_method      VARCHAR(32)  NOT NULL,          -- rule/semantic/hybrid/model/manual
    status            VARCHAR(16)  NOT NULL DEFAULT 'candidate', -- candidate/confirmed/rejected
    verified_by       VARCHAR(64),
    verified_at       TIMESTAMP,
    evidence_count    INT          NOT NULL DEFAULT 0,
    data_as_of        DATE         NOT NULL,          -- 输入数据截止日
    model_version     VARCHAR(32),
    created_at        TIMESTAMP    NOT NULL DEFAULT now(),
    UNIQUE (enterprise_id, chain_id, segment_id, product_id, model_version)
);
CREATE INDEX idx_ecp_ent ON ent_chain_position (enterprise_id, match_level);
CREATE INDEX idx_ecp_seg ON ent_chain_position (segment_id, status, match_score DESC);

-- ② 证据明细表（1:N，解释层的数据来源，必须逐条可溯源）
CREATE TABLE ent_chain_evidence (
    id             BIGSERIAL PRIMARY KEY,
    position_id    BIGINT       NOT NULL REFERENCES ent_chain_position(id) ON DELETE CASCADE,
    signal_type    VARCHAR(32)  NOT NULL,   -- scope/product/patent/qualify/supply/finance/text/cert
    field_path     VARCHAR(256) NOT NULL,   -- 精确到输入字段路径，如 enterprise.business_scope
    field_value    TEXT         NOT NULL,   -- 原文片段，不做改写
    matched_term   VARCHAR(128),            -- 命中的环节关键词/分类码
    weight         NUMERIC(5,4) NOT NULL,   -- 该证据的贡献权重
    source         VARCHAR(64)  NOT NULL,   -- 数据来源系统
    source_date    DATE,                    -- 该证据本身的时间
    CHECK (weight >= 0 AND weight <= 1)
);

-- ③ 环节价值画像（按区域+周期快照，招商价值的分母）
CREATE TABLE segment_value_profile (
    segment_id        VARCHAR(64) NOT NULL,
    region_code       VARCHAR(12) NOT NULL,
    period            VARCHAR(7)  NOT NULL,   -- 2026-09
    strategic_score   NUMERIC(5,2),           -- 战略重要性 S
    value_added_score NUMERIC(5,2),           -- 附加值 V
    scarcity_score    NUMERIC(5,2),           -- 稀缺度 R
    growth_score      NUMERIC(5,2),           -- 增长性 G
    total_score       NUMERIC(5,2),           -- SV 合成
    local_firm_count  INT,                    -- 本地该环节企业数
    local_leader_count INT,                   -- 本地链主/龙头数
    gap_level         VARCHAR(16),            -- none/low/mid/high/critical
    factor_snapshot   JSONB,                  -- 全部中间量，供复算
    PRIMARY KEY (segment_id, region_code, period)
);

-- ④ 企业产业链评分快照（按周期，支持"为什么上月A这月B"）
CREATE TABLE ent_chain_score (
    enterprise_id   VARCHAR(64) NOT NULL,
    chain_id        VARCHAR(64) NOT NULL,
    period          VARCHAR(7)  NOT NULL,
    segment_sv      NUMERIC(6,2),             -- 环节价值
    firm_cf         NUMERIC(5,3),             -- 竞争力系数
    risk_rd         NUMERIC(5,3),             -- 风险折减
    icv_score       NUMERIC(6,2),             -- 产业链价值分
    rank_in_segment INT,
    rank_total      INT,
    factor_breakdown JSONB NOT NULL,          -- 因子分解，解释层直接读
    data_gaps       JSONB,                    -- 缺失字段清单
    PRIMARY KEY (enterprise_id, chain_id, period)
);

-- ⑤ 决策档位与建议
CREATE TABLE ent_chain_decision (
    enterprise_id     VARCHAR(64) NOT NULL,
    region_code       VARCHAR(12) NOT NULL,
    period            VARCHAR(7)  NOT NULL,
    decision_type     VARCHAR(24) NOT NULL,   -- invest_promotion/cooperation/tracking
    grade             VARCHAR(8)  NOT NULL,   -- S/A/B/C
    attractiveness    NUMERIC(6,2),
    landing_prob      NUMERIC(5,4),           -- 落地可能性 LP
    carrier_match     NUMERIC(5,4),           -- 载体匹配度 FM
    veto_hits         JSONB,                  -- 命中的否决项
    expansion_signals JSONB,                  -- 扩张信号明细
    recommendation    TEXT,
    explanation       JSONB NOT NULL,         -- 归因链，结构见 schema 文件
    PRIMARY KEY (enterprise_id, region_code, period, decision_type)
);

-- ⑥ 规则命中审计（反馈闭环的载体）
CREATE TABLE match_rule_hit (
    id            BIGSERIAL PRIMARY KEY,
    rule_id       VARCHAR(64) NOT NULL,
    enterprise_id VARCHAR(64) NOT NULL,
    segment_id    VARCHAR(64) NOT NULL,
    hit_at        TIMESTAMP   NOT NULL DEFAULT now(),
    human_action  VARCHAR(16),        -- accept/correct/reject/null
    human_segment VARCHAR(64),        -- 人工纠正后的环节
    operator      VARCHAR(64)
);
```

### 4.2 为什么这样设计

- **`position` 与 `evidence` 分表**：一条定位可能有 8 条证据，混在 JSON 里无法做"按信号类型统计准确率"，也无法在人工核验界面逐条打勾。
- **一切带 `period` / `data_as_of`**：产业链数据时效性强，无时间戳的评分等于无法追责。
- **`factor_snapshot` / `factor_breakdown` 用 JSONB 存全量中间量**：解释层不做二次计算，直接读快照，保证"看到的分 = 当时算的分"。
- **`match_rule_hit.human_action` 是资产**：业务人员每一次纠正都是标注数据，三个月就能养出比纯规则强得多的模型。

## 5. L1 映射层：企业 → 环节归属

### 5.1 八类信号与强度分级

| 信号 | 来源字段 | 强度 | 使用要点 |
|---|---|---|---|
| **资质/行政许可** | 监管数据：GMP、危化品许可、建筑资质、医疗器械注册证、生产许可证 | ★★★★★ | 最强约束，可直接锁定环节；有排他性（无证不得生产） |
| **供应链关系** | 客户/供应商名单、招投标标的、海关 HS 编码 | ★★★★★ | 唯一定位**上下游位置**的信号，同时验证环节归属 |
| **产品/服务目录** | 企业自报产品、电商/官网 SKU、招投标标的物 | ★★★★ | 可直接连 `product` 节点，粒度最细 |
| **专利 IPC/CPC** | 知识产权数据 | ★★★★ | 技术环节定位最稳；注意区分"研发方向"与"实际主业" |
| **募投/融资用途** | 融资事件、招股书、公告 | ★★★ | 指示 **potential**（未来环节），不能当现有环节 |
| **经营范围文本** | 工商登记 | ★★ | 噪声最大，"技术服务/销售"类万能词必须进停用词表；需同义词与上下位词扩展 |
| **官网/年报/招聘 JD 语义** | 爬虫、招聘平台 | ★★ | 向量召回主力，做长尾覆盖 |
| **行业分类码 GB/T 4754** | 工商登记 | ★★ | 只能做**粗筛与先验**，粒度到"链"不到"环节" |

### 5.2 三阶段流水线

```
① 召回 Recall        行业码先验 + BM25 关键词 + 向量 ANN  →  Top-50 环节候选
② 精排 Rank          交叉编码器 / LightGBM
                     特征 = 信号命中向量(8维) + 命中证据数 + 企业规模 + 环节先验概率
③ 校准定档 Calibrate  Isotonic/Platt 校准到真实概率 → 阈值分层 → 弃权
```

**阈值分层（必须做，这是"不乱贴标签"的关键）**

| 校准概率 | match_level | 处理 |
|---|---|---|
| ≥ 0.85 | primary | 直接采用，进入评分 |
| 0.60 ~ 0.85 | secondary | 展示为"次要环节"，可参与评分但权重减半 |
| 0.40 ~ 0.60 | potential | 展示为"疑似/潜在"，**不进招商决策**，进人工核验队列 |
| < 0.40 | — | **弃权（abstain）**，宁可空着，绝不硬猜 |

> 弃权率是健康指标，不是失败指标。初期弃权率 15~25% 属正常，硬压到 5% 以下必然带来大量误标。

### 5.3 冷启动方案（没有标注数据时怎么办）

1. **LLM 生成环节定义卡**：为每个环节生成"定义 + 典型产品 + 正例 5 条 + 负例 5 条"，作为规则与弱标注基础。
2. **规则先跑全量**：资质类 + 供应链类强规则先落地，能覆盖 40~60% 企业且准确率极高。
3. **人工核验建黄金集**：分层抽样 500~1000 家（每链每环节 ≥20 家，**必须含边界企业与负例**），双专家独立标注，Cohen's Kappa ≥ 0.7 才可用于评测。
4. **负例挖掘是重点**：同链不同环节（"锂电池制造" vs "锂电设备制造"）、同名不同义（"芯"可能指电芯/芯片/灯芯）、集团与子公司环节错位。这三类是误标的主要来源。

## 6. L2 价值层：产业链价值分（ICV）

### 6.1 主公式

```
ICV = Σ_i [ w_i × SV(segment_i) ] × CF × RD

  SV : 环节价值 0~100        w_i : 主环节 0.7 / 次环节 0.2 / 潜在环节 0.1
  CF : 企业竞争力系数 0.4~1.6
  RD : 风险折减系数 0.5~1.0
```

### 6.2 SV 环节价值：四个子维度

| 维度 | 含义 | 数据来源 | 招商意义 |
|---|---|---|---|
| **战略重要性 S** | 是否属国家/省市重点目录、"卡脖子"清单、国产替代率低的环节 | 政策文本、产业规划、目录 | 决定"该不该补这条链" |
| **附加值 V** | 环节平均毛利率、微笑曲线位置（研发/品牌 高，组装/代工 低） | 上市公司分部数据、行业研报 | 决定"补进来值不值" |
| **稀缺度 R** | 区域内该环节企业密度、链主配套缺口 | 本地企业库 + `segment_gap` | **招商价值核心**：本地缺 = 招进来有位置 |
| **增长性 G** | 环节市场规模 CAGR、链上该环节投融资事件热度 | 行业数据、融资事件流 | 决定"是不是在风口上" |

> 稀缺度 R 是最容易被忽略、却对招商最关键的维度。一家普通企业在"本地空白环节"的招商价值，可能高于一家优秀企业在"本地已饱和环节"的价值。

### 6.3 CF 企业竞争力：五个子维度

| 维度 | 指标 | 归一化方式 |
|---|---|---|
| 规模经营 | 营收、营收增速、纳税额、社保人数 | **同区域同行业分位数**（避免跨行业不可比） |
| 创新 | 发明专利数、高价值专利占比、研发投入占比、参与标准制定 | 同行业分位数 |
| 资本 | 最新融资轮次、估值、投资方质量（头部机构加分） | 分级映射 |
| 资质荣誉 | 专精特新"小巨人"、高新技术企业、制造业单项冠军、瞪羚/独角兽 | 加分项枚举表 |
| 供应链地位 | 是否链主一级供应商、客户集中度、是否掌握稀缺产能 | 供应链数据 |

### 6.4 RD 风险折减：分级扣分

| 风险事件 | 折减 |
|---|---|
| 失信被执行人 | 直接进否决项，RD = 0.5 且档位封顶 C |
| 重大环保处罚未整改 / 重大安全事故 | RD = 0.6 |
| 被执行人、行政处罚（已结案缴款） | RD = 0.85~0.95 |
| 经营异常名录、股权高比例质押 | RD = 0.9 |
| 重大诉讼（作为被告，标的额 > 净资产 20%） | RD = 0.85 |
| 无风险记录 | RD = 1.0 |

### 6.5 三条工程铁律

1. **权重全部外置 YAML**，不同产业链、不同区域用不同权重集；硬编码权重的系统上线即僵化。
2. **所有维度先做分位数归一再合成**，直接用绝对值会让大行业企业永远碾压小行业。
3. **每次评分必须落快照 + 因子分解**，否则解释层无米下锅，也无法回答"为什么变了"。

## 7. L3 决策层：三张判定卡

### 7.1 招商吸引力指数

```
吸引力 = ICV × LP(落地可能性) × FM(载体匹配度)

LP 扩张信号（近 12 个月，按权重累加，上限 1.0）：
  · 新增分支机构 / 对外投资设立子公司        +0.25
  · 新增用地、环评公示、建设工程规划许可      +0.30   ← 最硬的扩产信号
  · 招聘量环比激增 > 100%                    +0.15
  · 完成新一轮融资（尤其含产业资本）          +0.20
  · 募投项目出现异地布局表述                  +0.20
  · 新增专利/软著且申请人地址出现新区域       +0.10

FM 载体匹配度：
  · 本地是否有对应链主，且其供应商缺口含该环节产品   0~0.4
  · 本地是否有匹配园区/载体/厂房条件                0~0.3
  · 本地政策条款是否覆盖该环节（补贴、税收、人才）   0~0.3
```

| 档位 | 吸引力 | 行动建议 |
|---|---|---|
| **S** | ≥ 85 | 重点招引，专班对接，纳入领导包联清单 |
| **A** | 70 ~ 85 | 主动对接，招商部门跟进，30 天内触达 |
| **B** | 55 ~ 70 | 储备跟踪，季度回访，等待窗口期 |
| **C** | < 55 | 观察，仅数据更新，不投入招商资源 |

### 7.2 硬性否决项（Hard Veto）—— 业务可信度的关键

**不论分数多高，命中即降档，且在解释层必须显式列出：**

- 失信被执行人 / 限制高消费（企业或法定代表人、实际控制人）
- 重大环保、安全、质量处罚**未整改结案**
- 实际控制人涉刑事案件、股权被司法冻结 > 50%
- 已列入本地招商黑名单 / 有违约退地记录
- 数据严重过期（核心字段 as_of 超过 18 个月）→ 不给档位，只给"数据待更新"

> 没有否决项的评分系统，第一次把一家失信企业推成 S 档，业务部门就再也不会用它。

### 7.3 合作配套价值 & 跟踪优先级

- **合作配套价值** = 与本地链主的产品-采购匹配度 + 供应稳定性（经营年限、产能利用率）+ 资质合规性。服务于"以商招商"和链主配套对接。
- **跟踪优先级** = 分值变化速率（环比 Δ）+ 事件触发（融资、诉讼、扩产、专利、高管变动、被并购）。用于生成"本周值得看的 20 家企业"。

## 8. L4 解释层：归因链四段式

**结论 → 因子 → 字段 → 证据**，四段缺一不可。

```json
{
  "conclusion": "招商档位 A（主动对接）",
  "score": 78.4,
  "baseline": 60.0,
  "drivers": [
    {
      "factor": "环节稀缺度",
      "contribution": 12.6,
      "direction": "positive",
      "evidence": [
        {"field": "segment_value_profile.local_firm_count", "value": 3,
         "source": "本地企业库", "as_of": "2026-09-30"},
        {"field": "segment_value_profile.gap_level", "value": "high",
         "source": "环节缺口模型", "as_of": "2026-09"}
      ]
    },
    {
      "factor": "扩张信号-新增用地",
      "contribution": 8.0,
      "direction": "positive",
      "evidence": [
        {"field": "expansion.land_use_permit", "value": "2026-07 新增工业用地规划许可 1 项",
         "source": "自然资源局公示", "as_of": "2026-07-15"}
      ]
    },
    {
      "factor": "风险折减-行政处罚",
      "contribution": -6.2,
      "direction": "negative",
      "evidence": [
        {"field": "risk.admin_penalty", "value": "环保罚款 8 万元，2025-11 已缴款结案",
         "source": "信用中国", "as_of": "2025-11-20"}
      ]
    }
  ],
  "vetoes": [],
  "confidence": 0.82,
  "data_gaps": ["未获取 2025 年营业收入", "无海关进出口数据", "供应链关系仅覆盖 2 家客户"]
}
```

### 三条硬约束（写进 Prompt 与代码双向校验）

1. **可复算**：`Σ contribution + baseline == score`，误差 > 0.1 直接拒绝落库。
2. **可溯源**：每条 `evidence.field_value` 必须能在输入数据中原样找到；找不到即视为幻觉，整条结论作废。
3. **可认怂**：字段缺失一律进 `data_gaps`，**禁止用行业均值、同类企业中位数冒充该企业取值**。

## 9. 评测体系：没有评测就不要上线

| 层 | 指标 | 目标值 | 说明 |
|---|---|---|---|
| 映射层 | Precision@1 | ≥ 90% | 主环节判对的比例 |
| | Recall@3 | ≥ 95% | 正确环节出现在 Top-3 |
| | 人工核验一致率 | ≥ 92% | 与黄金集比对 |
| | 弃权率 | ≤ 8%（稳定期） | 初期 15~25% 正常 |
| 价值层 | 与专家排序 Spearman ρ | ≥ 0.75 | 分数排序是否符合业务直觉 |
| | 档位月度抖动率 | ≤ 10% | 抖动大说明模型不稳或数据噪声大 |
| 决策层 | 专家采纳率 | ≥ 70% | S/A 档线索业务是否愿意跟进 |
| | 误报率 | ≤ 15% | S/A 档被否决的比例 |
| | 线索转化率 | 建立基线后持续提升 | 终极业务指标 |
| 解释层 | 归因覆盖率 | 100% | 每个结论必须有 ≥1 条证据 |
| | 可复算率 | ≥ 98% | 因子分解求和能还原总分 |

**黄金集构建**：分层抽样，每链每环节 ≥ 20 家，**必须包含 30% 边界企业与负例**；双专家独立标注 + 第三方仲裁；Kappa ≥ 0.7 方可启用；每季度增补 10% 并淘汰过期样本。

**反馈闭环**：业务人员在核验后台的每一次"确认/纠正"、对线索的每一次"采纳/否决"，实时写回 `match_rule_hit` 与标注库 → 周级重训精排模型 → 月级复核权重配置。**这是本方案能否长期活下去的唯一决定因素。**

## 10. 落地路线图

### 一期（0~6 周）：打通"在哪"
- 建桥接域六张表；接入资质、供应链、专利三类强信号规则
- LLM 辅助映射（召回+证据抽取）跑通全量企业
- 上线人工核验后台（这是给业务人员的第一个可感知价值）
- 企业画像页新增"产业链定位卡"（仅展示定位 + 证据 + 置信度）
- **交付判据**：随机抽 100 家企业，主环节 Precision@1 ≥ 85%，每条定位 ≥ 2 条可溯源证据

### 二期（6~14 周）：打通"值多少"
- 环节价值画像（SV 四维）建模，权重 YAML 化，支持分链分区域配置
- 企业竞争力 CF、风险折减 RD 计算，评分快照落库
- 图谱节点企业清单智能排序 + 环节缺口分析看板
- **交付判据**：与 3 位业务专家的排序 Spearman ρ ≥ 0.7；因子分解可复算率 ≥ 98%

### 三期（14~24 周）：打通"该不该动 + 凭什么"
- 扩张信号数据接入（用地、环评、招聘、融资事件流）
- 招商吸引力指数、硬性否决项、载体匹配度
- 归因链四段式全量上线，解释可下钻到字段
- 线索推送 + 采纳/否决反馈闭环
- **交付判据**：S/A 档线索专家采纳率 ≥ 70%，误报率 ≤ 15%，否决项零漏判

## 11. 风险与红线

| 风险 | 后果 | 控制手段 |
|---|---|---|
| **LLM 幻觉** | 编造环节归属或数值，业务被误导 | LLM 只做"文本 → 候选环节 + 原文证据引用"；所有数值走确定性计算；证据字段必须能在输入中原样匹配，否则整条作废 |
| **过度自信贴标签** | 大量低质量定位污染图谱 | 强制弃权机制 + 阈值分层 + potential 不进决策 |
| **数据过期** | 用两年前的营收做今天的招商判断 | 全字段 `as_of`；核心字段超期 18 个月不给档位 |
| **跨行业不可比** | 大行业企业永远高分 | 同区域同行业分位数归一 |
| **权重僵化** | 业务调整需要改代码发版 | 权重、阈值、否决项全部外置配置 |
| **合规** | 数据来源与使用越界 | 明确数据授权范围；爬虫数据合规审查；企业敏感数据不出域；对外接口做字段级脱敏与权限控制 |
| **可解释性让位于精度** | 分数更准但没人敢用 | 原则：**宁可弃权，不可错判为 S 档** |
